# 订阅自动保种助手（MoviePilot V3 插件）

用 MP 官方订阅追剧；当勾选站点出现**同剧、同季、目标分辨率、且符合包含/排除规则的整季全集**时，清理该订阅及其产物，再下载整包。

目的只有两个：**方便长期保种**、**保证整季视频规格一致**。

> 为什么必须「先删旧、再下新」：旧的媒体库文件不删，新全集转移进来时 MP 会判定目标已存在而跳过刮削/整理。所以清理是下载的前置条件，不是可选步骤。

---

## 一、固定流程（内置，无需配置）

```
Cron 定时扫描（静默后台，不接管 MP 原生订阅搜索）
  ↓
只遍历 MP 原生「电视剧」订阅（手动添加的种子不在订阅表，天然排除）
  ↓
合并生效规则：插件全局 + 该订阅自带的 include / exclude
  ↓
在勾选站点检索资源
  ↓
判定链：站点 → 排除规则 → 宿主 MetaInfo 季集 → 多季排除 → 单集/分段闸门
      → 半季排除 → 季号与订阅严格相等 → 分辨率四档 → 全集证据 → 包含规则
  ↓
【候选收敛】同一订阅若有多份符合的整季全集，只保留做种数最高的一份
  ↓ 命中
【等待 15 分钟】每分钟复检整季全集种子是否仍可检索到
      · 连续 2 次检索不到 / 订阅已被删 → 取消，不删任何内容
  ↓ 到期仍在
【删除四件套】订阅 → 下载器种子（含种子文件）→ 下载侧具体文件
            → 媒体库具体文件 → 转移记录与下载历史
      · 删除前把「订阅 → 种子 hash → 下载路径 → 媒体库路径」证据链写进日志
  ↓ 媒体库目标路径已清空
【10 分钟后】把选中的那一份整季全集交给 MP 下载链，正常转移刮削
      · 观察窗共 15 分钟，期间冷却该订阅，防止重复清理
```

流程参数（15 分钟等待、2 次缺失阈值、10 分钟延迟、15 分钟观察窗）都固化在代码里，配置页不再出现。

## 二、配置页 7 项

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 关 | 开启后注册 Cron 扫描 + 每分钟队列复检两个宿主服务 |
| 测试模式 | **开** | 只打印日志（含证据链）并推送预警，不入队、不删除、不下载 |
| Cron 定时表达式 | `0 4 * * *` | 5 段：分 时 日 月 周，例如每天 04:00 |
| 分辨率 | 全部 | 四档单选，见下 |
| 监控站点 | 空 | 多选，从 `SiteOper.list_active()` 动态生成；留空 = 全部站点 |
| 包含规则 | 空 | 关键字 / 正则式，命中任意一条才处理；留空 = 不限制 |
| 排除规则 | 空 | 关键字 / 正则式，命中任意一条直接跳过；留空 = 不排除 |

另有「立即扫描一次」「校验规则」两个按钮：

- **先启用插件并点「保存」**，再点按钮。插件未启用时按钮会弹回「插件未启用」并写一条日志，不会静默无反应。
- 点击后会弹出结果回执（扫描条数 / 规则校验结论 / 失败原因），同时在插件日志里留下 `【立即扫描一次】` 或 `【校验规则】` 开头的记录。
- 两个按钮都仍受测试模式约束：测试模式下只记录、不入队、不删除、不下载。
- 实现说明：配置页由 V3 的 `FormRender.vue` 渲染，按钮用官方同款 `props.onclick` 字符串函数调用 `window.MoviePilotAPI.post`；顶层 `events` 只有详情页 `PageRender.vue` 支持，写在配置页会被静默忽略。对应插件 API 的 `auth` 必须是字符串 `bear`，写成布尔 `True` 会被宿主路由判定为 apikey 鉴权而返回 401。

### 分辨率分解

与 MP 原生订阅的分辨率下拉完全一致，四档单选：

| 选项 | 匹配到的资源 | 效果 |
|---|---|---|
| 全部 | 不限制 | 任何分辨率的整季全集都触发 |
| 4k | `2160p / 2160i / 4K / UHD` | 只认 4K 整包 |
| 1080p | `1080p / 1080i / FHD` | 只认 1080P 整包 |
| 720p | `720p / 720i` | 只认 720P 整包 |

选定一档后，新旧资源规格一致；未标注分辨率的资源按「宁可漏判」原则跳过。

## 三、包含 / 排除规则（对齐 MP 原生订阅）

### 语法

- **每行一条**：新增 = 加一行，删除 = 删掉该行；`#` 开头为注释，空行忽略。
- **普通文字按关键字子串匹配**，写 `A|B` 或量词表达式即正则；统一**忽略大小写**。
- 匹配范围：**标题 + 副标题 + 站点标签**。
- 保存配置时校验正则合法性；**任意一行非法即暂停扫描并推送通知**（避免"写错了被静默忽略，按更宽松的规则删了东西"）。点「校验规则」按钮可随时复查，返回里还会带上**上一轮被规则筛掉的真实标题样本**与最终选用的候选，用于验证规则是否筛对。

### 优先级与位置

```
排除规则（最先判定，命中任意一条直接跳过）
  ↓ 未命中
内置安全闸门：季集 / 跨季 / 单集 / 半季 / 同季 / 分辨率 / 全集证据
  ↓ 全部通过
包含规则（最后判定，配置后必须命中任意一条）
```

> 用户规则**只能收紧、不能放宽**内置安全闸门。所以哪怕包含规则只写了 `HDR`，分集、跨季、错分辨率的资源依然会被拒绝。

### 典型场景：同站点两份 2160p 全集（HDR / 非 HDR）

| 想要哪份 | 配置 | 示例填写 |
|---|---|---|
| 不带 HDR 的那份 | **排除** | `HDR\|HDR10\|DV\|杜比视界\|HLG` |
| 带 HDR 的那份 | **包含** | `HDR\|HDR10\|DV\|Dolby\s*Vision\|杜比视界` |
| 指定发布组 | 包含 | `-Pure@HDSWEB\|-ADWeb` |
| 只要原盘 / REMUX | 包含 | `REMUX\|BluRay` |
| 排除 DV 但保留普通 HDR | 排除 | `\bDV\b\|Dolby\s*Vision\|杜比视界` |

> 注意 `\bDV\b` 用单词边界，避免误伤标题里的其它字母组合；`HDR` 会同时命中 `HDR10` / `HDR10+`，通常正合预期。

### 自动叠加订阅自带规则（零配置）

插件会读取该订阅在 MP 里已填写的 `include` / `exclude`（就是你截图里那两个组件），合并规则为：

- **排除**：插件全局规则 ∪ 订阅自带规则（并集，任一命中即跳过，更保守）。
- **包含**：插件全局规则**优先**；插件没填时才跟随订阅自带的 `include`。
- 订阅自带规则若含非法正则，只记日志并忽略，不影响其它订阅。
- 日志会逐条打印「本订阅生效规则：包含 N 条（来源）、排除 M 条（全局 x + 订阅 y）」。

> 潜在冲突：订阅自带的 `include` 如果写死了 `1080p`，而插件分辨率选 `4k`，两者是 AND 关系，会导致 4K 整包被包含规则拒掉。此时在插件全局「包含规则」里填一条（例如 `2160p|4K`）即可覆盖订阅规则，或在订阅里清掉该条。

### 多候选择优（自动，不可配）

同一订阅同一轮若筛出多份合格整季全集，按 **做种数 → 体积 → 发布时间 → 标题字典序** 选唯一一份，其余略过并推送「检测到多份整季全集」通知；日志会列出被略过的标题。这样不会重复清理，更不会下载两份全集。**想精确选哪一份，请填包含/排除规则把候选收敛到 1 个。**

## 四、怎么判断「整季全集」

判定规则写在 `core.py`，内置部分不能改：

1. **站点**：只认勾选站点。
2. **宿主季集优先**：优先读 MP 搜索结果 `Context.meta_info`。`S01`（无集号）是完结季，`S01 E40` / `S01 E36-E40` 是分集或分段包，直接跳过。
3. **多季/跨季排除**：`S01-S03`、`Season 1-3`、`全3季` 一律不参与，防止跨季误删。
4. **单集/分段闸门**：标题**和副标题**都检查。中文 PT 站常把「第27-30集」写在副标题，而标题看起来和整包一模一样；`E01-E06` 这类范围写法属于分段包，不是整季。
5. **半季/分卷排除**：`Part1` / `Vol.2` / `前6集` / `上半` 等。
6. **同季严格校验**：种子季号必须与订阅指定季号**相等**，不等即跳过。
7. **分辨率**：按四档筛选。
8. **全集证据**：MP 识别为完结季，或标题/副标题带 `全N集 / 完结 / Complete / 全集 / 整季 / 合集` 等整包关键词。

> 第 8 步是防止把「干净标题的分段包」当成整包的最后一道内置闸门，原则是**宁可漏判，不可误判**。

真实 PT 站标题样例（29 条）已固化为单元测试 `SAMPLE_CASES`，覆盖 `全40集`、`第27-30集`、`S01E01-E06`、`第4季`、`1080i`、标题尾部 `[热门]` 等情况。

## 五、删除范围（固定，不可单独关闭）

| 步骤 | 删除内容 | 宿主入口 |
|---|---|---|
| L0 | MP 原生电视剧订阅任务 | `SubscribeOper.delete()` |
| L1 | 下载器内种子 **+ 种子文件**（qBittorrent / Transmission 由宿主适配） | `DownloadChain.remove_torrents(delete_file=True)` |
| L1b | 下载目录里证据链登记的具体文件 | `Path.unlink()` |
| L3 | 媒体库里证据链登记的具体文件 | `Path.unlink()` |
| L2 | 转移记录、下载历史 | `TransferHistoryOper` / `DownloadHistoryOper` |

**只删证据链登记的具体文件，绝不递归删目录**；路径过短、指向目录、不存在的路径一律跳过。

## 六、安装

1. 在 MoviePilot → 插件 → 添加第三方仓库，填入 `https://github.com/hmily91/MoviePilot-Plugins`。
2. 在插件列表找到「订阅自动保种助手」→ 安装。**从 3.2.0 及更早版本升级时，更新完成后必须重启 MoviePilot（或在插件管理里重新加载本插件）**：动态 API 路由在插件注册时一次性生成，旧进程里仍挂着按 apikey 鉴权的旧路由，不重载会让按钮继续 401。
3. 打开配置页：打开「启用插件」、**保持测试模式开启**、填好站点/分辨率/规则，然后点「保存」。保存会重新加载插件并注册两个按钮的 API 路由；**未保存 / 未启用时按钮会弹回「插件未启用」**。
4. 点「校验规则」确认规则合法，再点「立即扫描一次」。两个按钮都会弹出结果回执，日志里出现 `【校验规则】` / `【立即扫描一次】` 开头的记录，以及每条资源的规则命中、候选收敛与证据链。
5. 确认只会删你想删的内容后，再关闭测试模式并保存。

目录结构：

```
plugins.v3/subscribeautokeep/       # 目录名 = 主类小写
  __init__.py                      # 主类：生命周期 / Cron / 配置页 / 扫描 / 队列
  core.py                          # 纯 Python 判定引擎（规则 + 多候选择优）
  cleaner.py                       # 证据链收集 + 四件套清理
  pending_queue.py                 # 等待队列状态
  form.json                        # 配置页 Vuetify JSON 快照
  plugin.json                      # 插件元数据
  README.md
tests/v3/subscribeautokeep/test_core.py
package.v3.json                     # 插件市场索引
```

本地跑测试：

```bash
python -m unittest discover -s tests/v3/subscribeautokeep -v
python -m compileall -q plugins.v3/subscribeautokeep
```

## 七、日志与通知

日志逐条输出：订阅名称、季号、生效规则来源、站点、种子标题、副标题、识别到的分辨率、是否整季全集、命中的包含规则、逐层判定结果、候选收敛结果、等待倒计时、复检结果、清理各步骤结果、取消原因。

通知走 MP 原生通道（微信 / Telegram 等由宿主路由），固定发送：测试模式命中、检测到多份整季全集、进入等待队列、任务取消、已执行清理、已下载整季全集、配置有误。

「校验规则」按钮返回上一轮扫描的 `excluded_samples`（被排除规则筛掉的真实标题 + 命中的规则）与 `picked`（最终选用的候选），不用翻日志也能确认规则是否生效。

## 八、风险说明

- **删除不可回滚**。默认测试模式开启，务必先跑一轮核对证据链。
- **媒体库文件删除是最高危动作**，且现在固定执行。若媒体库目录里存在你手动放进去的、与订阅同路径的文件，也会被证据链命中。
- **规则写反会误删**：例如把「排除 HDR」填进「包含」，结果只保留 HDR 版。建议先用测试模式 + 「校验规则」回显的真实标题样本确认。
- **订阅自带 include 与插件分辨率可能冲突**（见第三节），出现"明明有 4K 全集却不命中"时先查这里。
- **硬链接 / 秒传场景**：删除下载侧文件可能影响其它仍在做种的媒体；删媒体库文件前请确认没有别的订阅共用同一路径。
- **删除转移记录后**，MP 可能把同一资源判定为「未转移」，从而重复下载或重复转移。
- 建议**关闭 MP 原生订阅的「洗版」开关**，避免与本插件的清理动作重叠。
- 自动下载整季全集会消耗站点下载额度；若站点额度紧张，请自行评估。
- 分级清理不是数据库事务，中途失败可能出现「订阅已删、文件还在」的部分完成状态，需看日志人工补处理。
- 尚未在真实 MoviePilot V3 宿主中完成安装/启停验证；建议先在测试模式实机跑一轮。
