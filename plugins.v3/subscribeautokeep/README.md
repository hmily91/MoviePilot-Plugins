# 订阅自动保种助手（MoviePilot V3 插件）

用 MP 官方订阅追剧；当勾选站点出现**同剧、同季、目标分辨率的整季全集**时，清理该订阅及其产物，再下载整包。

目的只有两个：**方便长期保种**、**保证整季视频规格一致**。

> 为什么必须「先删旧、再下新」：旧的媒体库文件不删，新全集转移进来时 MP 会判定目标已存在而跳过刮削/整理。所以清理是下载的前置条件，不是可选步骤。

---

## 一、固定流程（内置，无需配置）

```
Cron 定时扫描（静默后台，不接管 MP 原生订阅搜索）
  ↓
只遍历 MP 原生「电视剧」订阅（手动添加的种子不在订阅表，天然排除）
  ↓
在勾选站点检索资源
  ↓
判定链：站点 → 宿主 MetaInfo 季集 → 多季排除 → 单集/分段闸门
      → 半季排除 → 季号与订阅严格相等 → 分辨率四档 → 全集证据
  ↓ 命中
【等待 15 分钟】每分钟复检整季全集种子是否仍可检索到
      · 连续 2 次检索不到 / 订阅已被删 → 取消，不删任何内容
  ↓ 到期仍在
【删除四件套】订阅 → 下载器种子（含种子文件）→ 下载侧具体文件
            → 媒体库具体文件 → 转移记录与下载历史
      · 删除前把「订阅 → 种子 hash → 下载路径 → 媒体库路径」证据链写进日志
  ↓ 媒体库目标路径已清空
【10 分钟后】把命中的整季全集交给 MP 下载链，正常转移刮削
      · 观察窗共 15 分钟，期间冷却该订阅，防止重复清理
```

流程参数（15 分钟等待、2 次缺失阈值、10 分钟延迟、15 分钟观察窗）都固化在代码里，配置页不再出现。

---

## 二、配置页只有 5 项

| 配置 | 默认 | 说明 |
|---|---|---|
| 启用插件 | 关 | 开启后注册 Cron 扫描 + 每分钟队列复检两个宿主服务 |
| 测试模式 | **开** | 只打印日志（含证据链）并推送预警，不入队、不删除、不下载 |
| Cron 定时表达式 | `0 4 * * *` | 5 段：分 时 日 月 周，例如每天 04:00 |
| 分辨率 | 全部 | 四档单选，见下 |
| 监控站点 | 空 | 多选，从 `SiteOper.list_active()` 动态生成；留空 = 全部站点 |

另有一个「立即扫描一次」按钮（仍受测试模式约束）。

### 分辨率分解

与 MP 原生订阅的分辨率下拉完全一致，四档单选：

| 选项 | 匹配到的资源 | 效果 |
|---|---|---|
| 全部 | 不限制 | 任何分辨率的整季全集都触发 |
| 4k | `2160p / 2160i / 4K / UHD` | 只认 4K 整包 |
| 1080p | `1080p / 1080i / FHD` | 只认 1080P 整包 |
| 720p | `720p / 720i` | 只认 720P 整包 |

选定一档后，新旧资源规格一致；未标注分辨率的资源按「宁可漏判」原则跳过。

## 三、怎么判断「整季全集」（全部内置，不再有正则配置）

判定规则写在 `core.py`，不需要也不能在配置页改：

1. **站点**：只认勾选站点。
2. **宿主季集优先**：优先读 MP 搜索结果 `Context.meta_info`。`S01`（无集号）是完结季，`S01 E40` / `S01 E36-E40` 是分集或分段包，直接跳过。
3. **多季/跨季排除**：`S01-S03`、`Season 1-3`、`全3季` 一律不参与，防止跨季误删。
4. **单集/分段闸门**：标题**和副标题**都检查。中文 PT 站常把「第27-30集」写在副标题，而标题看起来和整包一模一样；`E01-E06` 这类范围写法属于分段包，不是整季。
5. **半季/分卷排除**：`Part1` / `Vol.2` / `前6集` / `上半` 等。
6. **同季严格校验**：种子季号必须与订阅指定季号**相等**，不等即跳过。
7. **分辨率**：按上表四档筛选。
8. **全集证据**：MP 识别为完结季，或标题/副标题带 `全N集 / 完结 / Complete / 全集 / 整季 / 合集` 等整包关键词。

> 去掉用户正则后，第 8 步是最后一道闸门：干净标题若既没被 MP 识别为完结季、也没有整包关键词，不会被当成全集。原则是**宁可漏判，不可误判**。

真实 PT 站标题样例（29 条）已固化为单元测试 `SAMPLE_CASES`，覆盖 `全40集`、`第27-30集`、`S01E01-E06`、`第4季`、`1080i`、标题尾部 `[热门]` 等情况。

## 四、删除范围（固定，不可单独关闭）

| 步骤 | 删除内容 | 宿主入口 |
|---|---|---|
| L0 | MP 原生电视剧订阅任务 | `SubscribeOper.delete()` |
| L1 | 下载器内种子 **+ 种子文件**（qBittorrent / Transmission 由宿主适配） | `DownloadChain.remove_torrents(delete_file=True)` |
| L1b | 下载目录里证据链登记的具体文件 | `Path.unlink()` |
| L3 | 媒体库里证据链登记的具体文件 | `Path.unlink()` |
| L2 | 转移记录、下载历史 | `TransferHistoryOper` / `DownloadHistoryOper` |

**只删证据链登记的具体文件，绝不递归删目录**；路径过短、指向目录、不存在的路径一律跳过。

## 五、安装

1. 在 MoviePilot → 插件 → 添加第三方仓库，填入 `https://github.com/hmily91/MoviePilot-Plugins`。
2. 在插件列表找到「订阅自动保种助手」→ 安装 → 启用。
3. 保持**测试模式开启**，点「立即扫描一次」，看日志里的命中判定与证据链。
4. 确认只会删你想删的内容后，再关闭测试模式并启用插件。

目录结构：

```
plugins.v3/subscribeautokeep/       # 目录名 = 主类小写
  __init__.py                      # 主类：生命周期 / Cron / 配置页 / 扫描 / 队列
  core.py                          # 纯 Python 全集判定引擎
  cleaner.py                       # 证据链收集 + 四件套清理
  pending_queue.py                 # 等待队列状态
  form.json                        # 配置页 Vuetify JSON 快照
  plugin.json                      # 插件元数据
  README.md
tests/v3/subscribeautokeep/test_core.py
package.v3.json                     # 插件市场索引
```

本地跑测试：

```bash
python -m unittest discover -s tests/v3/subscribeautokeep -v
python -m compileall -q plugins.v3/subscribeautokeep
```

## 六、日志与通知

日志逐条输出：订阅名称、季号、站点、种子标题、副标题、识别到的分辨率、是否整季全集、命中的判定层、结论与原因、等待倒计时、复检结果、清理各步骤结果、取消原因。

通知走 MP 原生通道（微信 / Telegram 等由宿主路由），固定发送 5 类：测试模式命中、进入等待队列、任务取消、已执行清理、已下载整季全集。

## 七、风险说明

- **删除不可回滚**。默认测试模式开启，务必先跑一轮核对证据链。
- **媒体库文件删除是最高危动作**，且现在固定执行。若媒体库目录里存在你手动放进去的、与订阅同路径的文件，也会被证据链命中。
- **硬链接 / 秒传场景**：删除下载侧文件可能影响其它仍在做种的媒体；删媒体库文件前请确认没有别的订阅共用同一路径。
- **删除转移记录后**，MP 可能把同一资源判定为「未转移」，从而重复下载或重复转移。
- 建议**关闭 MP 原生订阅的「洗版」开关**，避免与本插件的清理动作重叠。
- 自动下载整季全集会消耗站点下载额度；若站点额度紧张，请自行评估。
- 分级清理不是数据库事务，中途失败可能出现「订阅已删、文件还在」的部分完成状态，需看日志人工补处理。
- 尚未在真实 MoviePilot V3 宿主中完成安装/启停验证；建议先在测试模式实机跑一轮。
